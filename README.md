# SIMPLY BRIDGE — גרסה 0.22.2

## Docker מקומי — 0.22.2

הקונטיינר מאזין בפורט `4318`, רץ כמשתמש `node` שאינו root, ושומר את `DATA_DIR=/app/data` ב־volume בשם `simply-bridge-data`. קובץ `.dockerignore` הוא allowlist: תיקיית `data/`, כספות, קובצי `.env`, תיקיות העבודה וחבילות build אינן נכנסות ל־build context או לתמונה.

דרישות: Docker Desktop עם Docker Compose v2. יש להריץ את הפקודות מתיקיית הפרויקט.

Build:

```powershell
docker compose build --pull bridge
```

Start:

```powershell
docker compose up -d
```

Stop בלי למחוק נתונים:

```powershell
docker compose down
```

Logs:

```powershell
docker compose logs -f bridge
```

בדיקת health וגרסה:

```powershell
docker inspect --format '{{.State.Health.Status}}' simply-bridge-bridge-1
(Invoke-WebRequest http://127.0.0.1:4318/).Content | Select-String 'SIMPLY BRIDGE · v0.22.2'
```

Upgrade בלי למחוק את ה־volume (יש להחליף את התג בגרסה החדשה):

```powershell
$env:BRIDGE_IMAGE='simply-bridge:NEW_VERSION'; docker build --pull -t $env:BRIDGE_IMAGE .; docker compose up -d --no-deps --force-recreate bridge
```

גיבוי ה־volume לתיקייה הנוכחית:

```powershell
docker run --rm -v simply-bridge-data:/data:ro -v "${PWD}:/backup" alpine:3.20 tar -czf /backup/simply-bridge-data-backup.tgz -C /data .
```

שחזור בטוח ל־volume חדש (ה־volume הקיים אינו נמחק):

```powershell
docker volume create simply-bridge-data-restored
docker run --rm -v simply-bridge-data-restored:/data -v "${PWD}:/backup:ro" alpine:3.20 tar -xzf /backup/simply-bridge-data-backup.tgz -C /data
$env:DATA_VOLUME='simply-bridge-data-restored'; docker compose up -d --force-recreate
```

אפשר לשנות את כתובת הפרסום, הפורט, כתובת הקשירה ושם ה־volume באמצעות `PUBLIC_URL`, `HOST_PORT`, `BIND_IP` ו־`DATA_VOLUME`. אין להריץ `docker compose down -v` אלא אם רוצים למחוק במפורש את נתוני SIMPLY BRIDGE.

## התהליך הנוכחי

קובץ גדול מחולק פנימית לאצוות של 500 רשומות כדי שלא להחזיק בקשת HTTP ארוכה. כל האצוות של אותו Dry Run מוצגות כפעולה אחת עם כמות כוללת, אחוזים וסטטוס. נעילת הכספת אינה עוצרת פעולה שכבר החלה, ולאחר כניסה חוזרת אפשר לפתוח את הפעולה מרשימת הפעולות האחרונות.

ה־Dry Run קורא את היעד, בודק מיפויים ויוצר תוכנית כתיבה קפואה. ה־RUN מאמת שהתקבל בדיוק אותו סדר שאושר ומבצע אותו; הוא אינו מפרסר מחדש את קובץ המקור ואינו מריץ Dry Run מלא לכל רשומה. אפשר לבחור Dry Run בלבד, בקשת אישור לפני RUN, או RUN אוטומטי רק כאשר אין תקלות.

רשומות שונות נכתבות במקביל לפי `maxConcurrentRequests`. הפעולות של אותה רשומה נשארות בסדר. `maxRequestsPerSecond` מגביל את קצב ההתחלות, וברירת המחדל היא 10. תגובת HTTP 429 מפחיתה את הקצב האפקטיבי, מכבדת `Retry-After` ומנסה שוב את הדחייה הוודאית; היא אינה מפילה את כל הריצה. כשל ולידציה או הרשאה נשמר עבור הרשומה והריצה ממשיכה. תוצאת רשת לא ידועה נבדקת מול היעד; כתיבה חסרה בלבד נשלחת שוב.

הלוג למשתמש שומר בעיות ודילוגים, ללא שורת הצלחה לכל רשומה. רשומה שאין בה שינוי מדולגת כ״ללא מידע חדש לעדכון״. אפשר להוריד דוח תקלות מקוצר, לפתוח פרטי פעולה ולמחוק פעולה שהסתיימה.

## ייצוא ומיפוי

התנגשות של מפתח הצלבה אינה מפילה מיד את הייצוא. הממשק מציג את הרשומות המתנגשות ודורש לבחור איזו מהן תיכלל; הרשומות שהושמטו מתועדות במטא־דאטה. שדות שלא נכללו בקובץ אינם דורשים מיפוי בייבוא. שדות יעד לקריאה בלבד, נוסחה, מטא־דאטה וקבצים אינם מוצגים כיעדי כתיבה.

שדה מקור אחד יכול להתמפות לכמה שדות יעד. שני שדות מקור שונים אינם יכולים להתמפות לאותו שדה יעד באותה קבוצה, כדי למנוע דריסת ערך לא מוגדרת. מידע משדות קישור נארז בשדה JSON ייעודי לעיבוד מאוחר ב־Node-RED.

# SIMPLY BRIDGE — גרסת ניסוי 0.4

## הרצה
Node.js 22 ומעלה. הפעילו `start.cmd` ופתחו http://127.0.0.1:4318/ . אין צורך ב־npm install. השרת מקומי בלבד. שם תיקיית המקור נשאר כפי שהיה כדי לשמור על הכספת הקיימת.

הכניסה משתמשת בסיסמה הקיימת. החיבורים והפריסטים מוצפנים ב־data/connections.vault.json באמצעות AES-256-GCM ו־scrypt. הכספת ננעלת אחרי 15 דקות ללא פעילות; הפעלה מחדש דורשת כניסה חוזרת. אין שחזור סיסמה.

## חיבורים ומיפוי
הגדירו כתובת בסיס מלאה בכל דומיין, כולל פורט ונתיב אם נדרשים, משתמש API ומפתח API. בחירת חיבור מאפשרת לטעון את רשימת הישויות ואת המבנים. ישויות מוגנות מדולגות לפני בקשת מבנה.
באותו מסך בוחרים ישויות, קבוצות ושדות, מפתח הצלבה ושומרים פריסטים לכל חיבור עם ברירת מחדל. סימון ישות פותח קבוצות וסימון קבוצה פותח שדות; יש בחירת הכול בכל רמה.

## ייצוא ניסוי
לחצו **המשך לייצוא** ואז **שליפה ויצירת קובץ**. הייצוא משתמש בבחירה הנוכחית, גם לפני שמירת השינויים כפריסט, ומבקש `instance_data` עם `limit: [0, 10]` לכל ישות. יש גם הגבלה מקומית ל־10. אין סינון תאריכים בשלב זה ואין מעבר לעמוד הבא.

לאחר הצלחה מוצגים מספר הרשומות, תצוגה מקדימה והורדה. אם אחת הישויות נכשלת, אין הורדת חבילה חלקית. שדות קבצים מוחרגים ומפורטים ב־excludedFields; לא מתבצעת הורדת קבצים או מחיקה. הייצוא והבדיקות הם קריאה בלבד במערכת המקור.

## חוזה הקובץ
הסכימה `public/transfer.schema.json` מגדירה מעטפת פשוטה: `meta` ו־`entities`, ובכל ישות `meta` ו־`records`. התוכן ב־`data` חופשי; אין סכימה נפרדת לכל ישות. זו סכימה מוצעת לבדיקה, לא אישור אבטחת מידע.

- meta של החבילה: גרסת סכימה 1.0, מזהה חבילה, זמן יצירה, שם פריסט, מצב sample, מגבלה 10. ללא סודות חיבור או כתובת שרת.
- מפתח הישות ו־meta.dataName: ה־DATA NAME המקורי. meta כולל את השדות שנבחרו ומקור מפתח ההצלבה, מספר רשומות וחלון תאריכים null (ללא סינון).
- רשומה: id הוא מזהה המקור; matchKey הוא הערך שנבחר להצלבה. updatedAt נשמר כשזמין.
- data: מפת DATA NAME של קבוצות למערכי שורות. כל שורה ממפה DATA NAME של שדה לערך המקורי. גם קבוצה רגילה היא מערך עם שורה אחת. קבוצות חוזרות שומרות את השורות וסדרן. קבוצה ריקה מפורשת נשמרת כמערך ריק.
- שדה שה־API לא החזיר עבורו value אינו מתווסף; ערכי null, false, 0 ומחרוזת ריקה נשמרים. אין החלפת ערך חסר ב־null.
- מפתח הצלבה חייב להיות מחרוזת לא ריקה או מספר, וייחודי במדגם. מפתח חסר, מורכב או כפול עוצר את הייצוא. אין בכך בדיקת ייחודיות של כל בסיס הנתונים.

הייבוא העתידי יתאים ישויות לפי DATA NAME ויאפשר התאמה ידנית ושדה יעד ל־matchKey. id אינו מיועד לכפיית מזהה MongoDB זהה. ערכי קשר נשמרים כפי שהגיעו, כולל מזהי מקור; בשלב הייבוא יהיה צורך לפתור את הקשרים למזהי היעד ולהמיר לצורת הכתיבה שה־API דורש. לא בוצעה כתיבה או בדיקת ייבוא למערכת יעד בגרסה זו.

## עדכון 0.5 — חלון עדכון ו־Dry Run

במסך הייצוא יש סינון כברירת מחדל לשבעת הימים האחרונים: from כולל, to לא כולל, עד 10 רשומות לכל ישות. הזמנים מוצגים בזמן המקומי ונשלחים כ־UTC. ניתן לכבות סינון, לערוך תאריכים או לשמור התחלה לחיבור. סינון אינו מבטיח ייצוא מלא: זו עדיין דגימה עם limit [0,10].

`instance_data.lastModified` הוא תאריך המקור, שנשמר כ־updatedAt. בניסוי חי פילטר ישיר על lastModified או last_modified התעלם מהתנאי. הפילטר שעבד משתמש ב־DATA NAME של שדה מסוג metadata-field עם possible_values=last_modified. השדה מזוהה אוטומטית במבנה, בלי הסתמכות על שם בעברית. ישות ללא שדה כזה חסומה לייצוא מסונן. כל תאריך שחזר נבדק מול החלון; תוצאה ללא תאריך תקין או מחוץ לחלון עוצרת את הייצוא.

בדיקה חיה: 16 ישויות עם שדה מתאים, 29 ללא שדה מתאים, 41 רשומות במדגם השבוע. בתקלות: 13,852 ללא סינון, 778 תואמות לשבוע, 0 לתאריך עתידי. עשר הרשומות הראשונות היו זהות, מפני שכולן עודכנו בשבוע הזה; הספירה ובדיקת הבקרה הוכיחו שהסינון הופעל.

במסך הישויות מופיע אזור **ייבוא · Dry Run בלבד**. אפשר לטעון JSON, או לשלוח אליו את קובץ הייצוא החדש בכפתור. התאמת ישויות מתחילה לפי DATA NAME וניתנת לשינוי. בוחרים שדה יעד למפתח החיצוני לכל ישות, או _id לצורך בדיקה באותה סביבה בלבד. יש לטעון קודם את מבני חיבור היעד.

הבדיקה בונה חיפוש שוויון עם limit [0,2], מאמתת שהמפתח שהוחזר באמת תואם, וחוסמת התאמה מרובה או תוצאה חלקית. אם יש התאמה, תכנון update_instance_fields משתמש ב־_id של היעד ובשלשות שדה/ערך/אינדקס. אם אין התאמה ונבחר שדה חיצוני, תכנון create_instance כולל את matchKey בשדה היעד. לא נשלחות בקשות כתיבה: המנוע מאפשר רק entities_list, entity_structure, instance_data.

תכנון אינו אישור של השרת לכתיבה. שדות מחושבים, metadata, קבצים וקריאה בלבד מוחרגים. קשרים, ערכים מורכבים, טלפונים, תאריכים וקבוצות חוזרות עלולים לחסום את הרשומה עד להשלמת המרות ומדיניות התאמה. אינדקס מערך של קבוצה חוזרת אינו תחליף ל־group_index של היעד. חובה להמשיך טיפול במגבלות אלה לפני ייבוא אמיתי. הדוח מציג בנפרד התאמות לעדכון/מועמדות ליצירה ורשומות חסומות, וכולל בקשות מתוכננות עם sent=false.

הכספת שומרת לכל חיבור exportFrom (ערך התחלה ידני), lastImportedAt ו־sourceSyncedThrough. שני האחרונים נשארים null עד מימוש ייבוא אמיתי מוצלח. בדיקת Dry Run והפקת מדגם אינם מקדמים אותם. הדוח אינו מחליף היסטוריית ייבוא.

שיפור GUI של הפריסטים נשמר להמשך ב־TASKS.md.

## עדכון 0.7.1 — שדות מקור וטלפון
מיפוי הייבוא נגזר רק ממפתחות records.data, ולא מרשימת meta.fields. שם הקובץ מוצג כדי לזהות את חבילת הבדיקה. שדות יעד בתיבות הבחירה הם אפשרויות ולא דרישות ייבוא. בדיקת רגרסיה מאמתת ששדה OTP שלא נבחר אינו מיוצא.

## Deferred relation fields (v0.18.0)

When an imported source field is mapped to a target relation field, SIMPLY BRIDGE does not resolve or write that relation. Choose a non-repeating text/textarea target field for the relation JSON. Each record receives one JSON envelope with the original value and explicit ID, TEXT, VALUE, source-record and match-key candidates for later Node-RED processing. The complete JSON is limited to 9,999 characters.
